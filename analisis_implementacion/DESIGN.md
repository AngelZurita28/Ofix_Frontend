# Guia de identidad visual Ofiix

## Proposito del documento

Esta guia extrae y formaliza la identidad visual actual de Ofiix para que pueda aplicarse de forma consistente en:

- nuevas aplicaciones de la misma organizacion;
- modulos web o moviles;
- dashboards internos;
- presentaciones comerciales;
- videos explicativos;
- piezas para redes sociales;
- imagenes institucionales;
- materiales de onboarding para clientes y profesionales.

La marca no debe sentirse como una app generica de servicios. Debe sentirse como una plataforma local, confiable, protegida y cercana, con una capa de sofisticacion visual suficiente para comunicar seguridad financiera, privacidad y profesionalismo.

## Idea central de marca

Ofiix es una infraestructura de confianza para conectar necesidades domesticas o tecnicas con profesionales locales.

La identidad visual debe comunicar cuatro ideas al mismo tiempo:

1. **Cercania local**: personas reales, trabajos reales, zonas reconocibles, lenguaje humano.
2. **Proteccion**: escrow, privacidad de direccion, verificacion y trazabilidad.
3. **Calidez domestica**: el servicio ocurre en hogares, negocios y espacios cotidianos.
4. **Profesionalismo tranquilo**: no debe verse improvisado ni informal; debe sentirse operativo, limpio y confiable.

La metafora visual principal es:

> Vidrio esmerilado sobre materiales naturales: arena, arcilla, vegetacion y ceramica oscura.

Esto produce una interfaz con profundidad, calma y claridad. La marca no grita. Ilumina, contiene y guia.

## Personalidad visual

### Atributos principales

- Organica
- Local
- Humana
- Segura
- Tactil
- Serena
- Premium sin ostentacion
- Tecnologica sin frialdad
- Profesional sin rigidez corporativa

### Lo que debe evitar

- Estetica bancaria fria.
- Azul corporativo dominante.
- Morados y degradados genericos de startup.
- Fondos blancos planos sin atmosfera.
- Iconografia excesivamente infantil.
- Exceso de sombras duras.
- Paletas neon, crypto o cyber.
- Interfaces saturadas de tarjetas sin jerarquia.
- Apariencia de marketplace agresivo o de cupones.

## Territorio estetico

El territorio visual se puede describir como:

**Terrario funcional + ceramica pulida + luz de atardecer + vidrio de seguridad.**

La app debe parecer un objeto digital cuidado, casi fisico. Los paneles deben sentirse como laminas de vidrio esmerilado flotando sobre una base de arena calida. Los acentos de color aparecen como luz ambiental, no como plastas pesadas.

## Proporcion de color

Para interfaces:

- 65% arena, salvia o blanco cristal.
- 20% negro humus y textos tierra.
- 10% acento del modo activo.
- 5% estados, mapas, estrellas y elementos de soporte.

Para presentaciones:

- Fondos arena o salvia.
- Titulos negro humus.
- Un acento por slide.
- Usar naranja para problema/accion/cliente.
- Usar verde para profesional/progreso/confianza.

Para video:

- Evitar fondos planos.
- Usar halos lentos de naranja o verde sobre arena.
- El color debe aparecer como luz proyectada, no como bloque saturado.

## Gradientes y atmosfera

La atmosfera Ofiix se genera con luces difusas de gran escala.

### Halo principal

Usar un circulo o elipse muy grande, con blur alto:

```css
background-color: var(--accent);
filter: blur(140px);
opacity: 0.35 - 0.45;
```

En landing puede ocupar 40-50% del viewport. En dashboards debe reducirse y concentrarse cerca del navbar o del modulo activo.

### Halo secundario

Usar `--accent-light` con blur similar y opacidad menor. Debe dar soporte y no competir.

### Regla visual

Los halos nunca deben ser decoracion aislada y obvia. Deben parecer luz ambiental que atraviesa vidrio. Si se ven como circulos de color pegados al fondo, estan mal aplicados.

## Materiales visuales

### Vidrio esmerilado

Es el material principal de la interfaz. Debe aplicarse a paneles, modales, barras superiores, widgets y contenedores de informacion.

```css
.glass-panel {
  background:
    linear-gradient(145deg, rgba(255,255,255,0.58), rgba(255,255,255,0.28)),
    rgba(255,255,255,0.45);
  backdrop-filter: blur(16px);
  -webkit-backdrop-filter: blur(16px);
  border: 1px solid rgba(255,255,255,0.60);
  border-radius: 32px;
  box-shadow:
    0 14px 42px -18px rgba(105,95,87,0.12),
    inset 0 1px 0 rgba(255,255,255,0.62);
}
```

Principios:

- Transparencia alta, pero nunca al punto de perder legibilidad.
- Bordes luminosos, no grises.
- Sombras suaves y extendidas.
- El panel debe sentirse liviano, no plastico.

### Ceramica oscura

Usar Negro Humus `#181B19` para:

- botones primarios;
- headers de alta autoridad;
- tarjetas destacadas;
- momentos de decision;
- cierres de flujo;
- contrastes en materiales comerciales.

Debe sentirse como ceramica satinada, no como negro puro digital.

### Arena y arcilla

Arena es el lienzo. Arcilla es accion. Ambas deben convivir en una temperatura calida.

Usar arcilla/naranja para:

- contratar;
- publicar tarea;
- pagar;
- aceptar;
- urgencia;
- accion inmediata.

## Tipografia

### Familias principales

| Uso | Familia | Caracter |
|---|---|---|
| Titulos y UI destacada | `Outfit` | Geometrica, redondeada, moderna, cercana. |
| Texto largo y formularios | `Inter` | Clara, funcional, legible. |

Aunque `Inter` es una fuente comun, en esta identidad funciona como soporte sobrio para que `Outfit`, la paleta y los materiales carguen el caracter. Si otra app de la organizacion requiere mas personalidad editorial, puede sustituirse el cuerpo por `Satoshi`, `Manrope` o `IBM Plex Sans`, manteniendo `Outfit` como display.

### Jerarquia web recomendada

| Rol | Tamano | Peso | Line-height | Uso |
|---|---:|---:|---:|---|
| Hero principal | `46px` | `500` | `1.05` | Landing, claims principales, pantallas de entrada. |
| Titulo de seccion | `30px` | `500` | `1.15` | Dashboards, encabezados de modulo. |
| Titulo de tarjeta | `19px` | `500` | `1.25` | Trabajos, profesionales, contratos. |
| Body | `15px` | `400` | `1.45` | Descripciones, chat, instrucciones. |
| Boton | `14-15px` | `500` | `1.20` | CTAs, tabs, controles. |
| Micro etiqueta | `11px` | `600` | `1.30` | Badges, precios, metadata, estados. |

### Jerarquia para presentaciones

- Titulo de portada: Outfit 56-72, peso 500.
- Titulo de slide: Outfit 34-44, peso 500.
- Subtitulo: Inter 20-26, peso 400.
- Cuerpo: Inter 16-20, peso 400.
- Data/labels: Inter u Outfit 11-14, peso 600, mayusculas moderadas.

### Reglas tipograficas

- No usar pesos muy pesados como 800/900 salvo en una pieza publicitaria excepcional.
- No usar letter spacing negativo en UI compacta.
- Las micro etiquetas pueden usar `letter-spacing: 0.5px` y mayusculas.
- Los textos deben sentirse claros y humanos, no tecnicos.
- Titulos cortos, accionables y concretos.
- Evitar slogans abstractos que no expliquen el beneficio.

## Forma y geometria

La forma base de Ofiix es la piedra de rio: suave, pulida, continua.

### Radios

| Token | Valor | Uso |
|---|---:|---|
| `xs` | `6px` | Badges, checks, etiquetas pequenas. |
| `sm` | `14px` | Avatares, miniaturas, imagenes de portafolio. |
| `md` | `24px` | Tarjetas, burbujas de chat, mapas internos. |
| `lg` | `32px` | Paneles principales, modales, contenedores grandes. |
| `pill` | `9999px` | Botones, inputs, switches, chips. |

### Reglas de forma

- Botones e inputs deben ser tipo capsula.
- Paneles grandes deben tener esquinas amplias.
- Las tarjetas repetidas pueden ser un poco mas contenidas, pero nunca cuadradas.
- Iconos dentro de botones primarios deben vivir en circulos.
- Las imagenes de portafolio deben tener recorte suave, no esquinas duras.

## Layout y composicion

### Web app

La composicion debe priorizar claridad operacional:

- barra superior flotante;
- selector de modo visible;
- paneles glass sobre fondo atmosferico;
- columnas funcionales para filtros, tareas y detalles;
- mapas o listas como superficies de trabajo;
- CTAs claros y contextuales.

Los dashboards no deben convertirse en landing pages. Deben sentirse como herramientas de trabajo elegantes.

### Landing

La primera pantalla debe explicar la dualidad:

- contratar;
- ofrecer.

Debe mostrar la promesa de privacidad y escrow pronto, no escondida al final.

La composicion puede ser mas editorial y amplia, pero debe dejar claro que la app funciona como una plataforma transaccional.

### Presentaciones

Recomendacion por slide:

- fondo arena;
- una banda o halo del modo;
- titulo corto;
- una visual principal;
- maximo tres bloques de informacion;
- usar vidrio para contener datos, no para decorar todo.

### Video

Tratamiento recomendado:

- fondos con movimiento lento de luz;
- transiciones tipo deslizamiento suave;
- overlays de vidrio para texto;
- iconos lineales;
- close-ups de UI;
- alternancia naranja/verde para explicar los dos lados del marketplace.

## Componentes visuales canonicos

### Boton primario

Boton tipo capsula en Negro Humus, texto blanco y circulo de icono al extremo derecho.

Comportamiento:

- hover levanta 1-2px;
- sombra se intensifica;
- el circulo cambia al acento activo;
- icono puede rotar suavemente si representa avance.

Uso:

- Solicitar tarea.
- Ofrecer mi servicio.
- Aceptar propuesta.
- Fondear garantia.
- Completar trabajo.

### Boton secundario

Capsula de vidrio claro con borde frost.

Uso:

- filtros;
- volver;
- acciones no destructivas;
- abrir configuracion;
- ver detalles.

### Inputs

Inputs tipo capsula:

- fondo blanco translucido `rgba(255,255,255,0.65)`;
- borde frost;
- icono lineal a la izquierda;
- focus con borde de acento y halo suave.

No usar inputs rectangulares tradicionales.

### Badges

Badges pequenos, de radio `6px`, texto en mayusculas moderadas.

Tipos:

- verificacion;
- categoria;
- urgencia;
- estado de contrato;
- disponibilidad;
- escrow.

### Cards

Las cards deben parecer objetos livianos:

- vidrio o blanco translucido;
- sombra baja;
- borde luminoso;
- separacion clara;
- encabezado fuerte;
- metadata en tierra sombreada.

No encerrar cards dentro de otras cards salvo modales o widgets muy especificos.

### Mapas

El mapa Ofiix no debe sentirse como mapa tecnico frio. Debe tener:

- base arena `#E6DFD5`;
- reticula piedra `#D8D0C4`;
- elementos acuosos muy suaves `#CAD5E2`;
- pines con acento de modo;
- circulos de privacidad visibles pero discretos.

Para mapas reales, estilizar tiles hacia arena/salvia y bajar saturacion de calles.

## Iconografia

Estilo:

- lineal;
- redondeado;
- trazo consistente;
- sin rellenos pesados;
- preferentemente lucide o familia similar.

Iconos clave:

- ubicacion;
- escudo;
- mensaje;
- estrella;
- herramienta;
- dinero/escrow;
- reloj;
- check;
- documento;
- usuario/profesional.

Reglas:

- Usar iconos como apoyo de lectura, no como ilustracion decorativa principal.
- No mezclar estilos de icono.
- Evitar iconos caricaturescos.
- En botones pequenos, priorizar simbolo sobre texto cuando el significado sea comun.

## Fotografia e imagenes

### Direccion fotografica

La fotografia debe mostrar:

- profesionales reales;
- herramientas;
- hogares o negocios en contexto;
- manos trabajando;
- materiales honestos;
- resultados terminados;
- retratos con luz natural.

Tratamiento:

- luz calida o natural;
- bajo contraste agresivo;
- fondos reales pero ordenados;
- color corregido hacia arena, arcilla o verde natural;
- recortes con radio suave.

Evitar:

- stock corporativo evidente;
- sonrisas exageradas;
- cascos industriales si no aplican;
- fondos azules de tecnologia;
- imagenes demasiado oscuras;
- fotos que no permitan entender el oficio.

### Imagen institucional

Para banners o portadas:

- usar una escena real o generada de un hogar/servicio;
- superponer texto directamente, no dentro de una tarjeta pesada;
- aplicar veladura calida si el texto necesita contraste;
- mantener un halo de acento sutil.

## Motion design

La animacion debe sentirse calmada y material.

### Duraciones

- Micro-interaccion: 180-300ms.
- Cambio de modo: 400-800ms.
- Entrada de modal: 350-450ms.
- Halos ambientales: 12-22s.
- Video/transiciones: 600-1200ms.

### Curva recomendada

```css
cubic-bezier(0.16, 1, 0.3, 1)
```

### Principios

- Movimiento suave, no elastico infantil.
- Los elementos aparecen con leve ascenso y opacidad.
- Los halos respiran lentamente.
- El cambio entre demanda/oferta debe sentirse como un cambio de luz ambiental.
- Respetar `prefers-reduced-motion`.

## Voz visual y comunicacion escrita

Aunque este documento se centra en visual, la identidad depende del tono de texto.

### Voz

- Clara.
- Cercana.
- Directa.
- Profesional.
- Protectora.
- Sin tecnicismos innecesarios.

### Frases que encajan

- "Contrata con contexto, privacidad y garantia."
- "Tu oficio convertido en oportunidades cercanas."
- "El pago queda protegido hasta terminar el trabajo."
- "La direccion exacta se libera cuando el trato esta fondeado."
- "Compara propuesta, perfil y precio antes de aceptar."

### Evitar

- "La mejor app del mercado."
- "Servicios al instante garantizados."
- "Gana dinero facil."
- "Revolucionamos el futuro de..."
- Lenguaje de urgencia agresiva.

## Aplicacion por modo

### Demanda

Visual:

- acento naranja;
- fondos arcilla claros;
- CTAs orientados a publicar, contratar y pagar;
- mapas con pines de profesionales;
- sensacion de resolver sin perder control.

Mensajes:

- privacidad;
- comparacion;
- seguridad de pago;
- direccion protegida;
- ayuda cercana.

### Oferta

Visual:

- acento verde;
- badges de reputacion;
- estado online;
- tablero de oportunidades;
- mapas con zonas aproximadas de tarea;
- sensacion de profesion, ingreso y confianza.

Mensajes:

- oportunidades cercanas;
- perfil visible;
- postular con propuesta;
- no salir antes del escrow;
- reputacion y cobro protegido.

## Escrow y confianza visual

El escrow debe verse como una capa de seguridad, no como un tramite financiero frio.

Elementos:

- escudo lineal;
- progreso por pasos;
- monto protegido en tarjeta destacada;
- estados con color medido;
- mensajes de sistema en chat;
- direccion bloqueada/desbloqueada.

Estados visuales:

- `pending_deposit`: arcilla suave, llamada a accion clara.
- `funded`: verde terraria, escudo activo, direccion liberada.
- `completed`: negro humus + verde, cierre serio.
- `disputed`: usar rojo solo como acento pequeno, con mucho fondo neutro.

## Accesibilidad visual

Reglas minimas:

- Texto principal siempre en `#181B19` sobre fondos claros.
- Texto secundario en `#5E544C`, no mas claro.
- No depender solo del color: usar iconos, labels y texto.
- Focus visible con `--accent-text`.
- No poner texto pequeno sobre halos saturados.
- En materiales de video, asegurar subtitulos con fondo o sombra suficiente.
- Las transparencias deben tener fallback opaco para baja compatibilidad.

## Guia para nuevas apps de la organizacion

Si se crea otra app bajo la misma organizacion, debe conservar:

- arena como base;
- negro humus como autoridad;
- vidrio esmerilado como material;
- esquinas organicas;
- halos ambientales;
- tipografia Outfit + Inter o equivalente cercano;
- acentos por contexto;
- lenguaje de confianza local.

Puede cambiar:

- el acento principal si el producto no usa demanda/oferta;
- la densidad del layout;
- la cantidad de glassmorphism;
- el protagonismo fotografico;
- la escala tipografica.

No debe cambiar:

- la temperatura calida general;
- el principio de privacidad/confianza;
- la suavidad material;
- el uso sobrio del color;
- el tono humano y directo.

## Guia para videos

### Intro

- Fondo arena.
- Halo lento naranja o verde.
- Logo en negro humus o azul profundo.
- Entrada suave con blur/fade.

### Explicacion de flujo

- Usar naranja para cliente.
- Usar verde para profesional.
- Usar escudo/vidrio para escrow.
- Mostrar la direccion exacta como dato protegido que se desbloquea.

### Lower thirds

- Capsulas de vidrio.
- Texto Outfit para nombre/titulo.
- Texto Inter para descripcion.
- Acento pequeno del modo.

### Transiciones

- Cambio de luz ambiental.
- Deslizamiento de paneles.
- Zoom suave hacia cards o mapas.
- Evitar glitches, flashes o efectos tech ruidosos.

## Guia para presentaciones

### Portada

- Fondo arena con halo grande.
- Logo superior o centrado.
- Titulo en Outfit.
- Subtitulo en Inter.
- Un solo acento.

### Slide de problema

- Usar Demanda/naranja.
- Mostrar tension de forma calmada: tarea, urgencia, privacidad.
- No usar rojo salvo para errores reales.

### Slide de solucion

- Usar vidrio + negro humus.
- Mostrar flujo en 3 pasos.
- Incluir iconos lineales.

### Slide de marketplace

- Usar dualidad naranja/verde.
- Dividir cliente/profesional de forma clara.
- Mantener fondo comun arena para expresar conexion.

### Slide financiero

- Usar negro humus y verde.
- Escudo como simbolo.
- Monto protegido en capsula.
- Evitar look bancario azul.

## Do / Don't

### Hacer

- Usar fondos calidos.
- Dar profundidad con vidrio y blur.
- Usar acentos como luz.
- Mantener CTAs negros con icono circular.
- Redondear contenedores con generosidad.
- Usar mapas suaves y no invasivos.
- Mostrar personas y trabajos reales.
- Comunicar privacidad desde lo visual.

### No hacer

- No usar blanco plano como unica base.
- No usar azul corporativo como color principal.
- No usar degradados morados genericos.
- No usar esquinas rectas en componentes principales.
- No usar sombras duras tipo ecommerce.
- No usar iconos rellenos mezclados con lineales.
- No convertir cada seccion en una tarjeta flotante.
- No saturar una pantalla con naranja o verde.

## Checklist visual de aprobacion

Antes de publicar una pieza o pantalla, validar:

- Se reconoce la atmosfera arena/vidrio.
- El acento corresponde al contexto: demanda naranja, oferta verde.
- Hay suficiente contraste en textos.
